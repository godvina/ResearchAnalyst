The Agent Chain Architecture
Sequential agents — each one sees and builds on the findings of all previous agents
Agent 1
Broad Scanner
Job: Survey all available literature on the research topic. Find key facts, anomalies, counter-arguments.

Input: Research question string
Output: Summary, 15 key facts, 7 anomalies, 8 counter-arguments, 25 sites identified
Time: 83 seconds
Example finding: "Jim Alison (2001) great-circle passing through Giza, Easter Island, Nazca within <1° arc over 40,000km"
→
Agent 2
Taxonomy Scanner
Job: Score findings against the signature taxonomy. Find SPECIFIC cross-site patterns with citations.

Input: Broad Scanner findings + taxonomy
Output: 6 signature matches with researcher citations + web sources
Time: 80 seconds
Example: "Orion correlation — Giza, Angkor, Teotihuacan encode same precessional epoch (10,500 BCE)"
→
Agent 3
Cross-Pattern Agent
Job: Find the "documentary gold" — same technique at sites 5000km+ apart. Uses Tavily web search for sourcing.

Input: All previous findings + sites list
Output: Cross-site connections with distances + researchers
Time: ~80 seconds (when triggered)
Example: "Polygonal masonry at Sacsayhuaman AND Mycenae — 12,000km apart, same fitting technique"
Key Design Decision: Each agent sees ALL accumulated findings from previous agents. This enables compounding intelligence — Agent 3 can find connections that Agent 1 surfaced but didn't recognize as significant. The orchestrator manages context passing, error recovery, and auto-triggers follow-up agents based on each agent's suggested_follow_ups field.

From Findings to Interactive Visualization
How agent output becomes explorable intelligence in the dashboard
DATA PIPELINE
1
Agent Chain Produces JSON
Each agent returns structured findings + signature_matches. Saved to agent-chain-results.json
2
Merge into Scored Findings
Merge script maps sites → node IDs, extracts specific indicators, upgrades confidence levels. Saved to uvg-grid-scored-findings.json
3
Frontend Renders Network Graph
D3 force-directed graph draws edges ONLY between nodes sharing SPECIFIC (non-generic) indicators. Generic matches filtered out.
4
Documentary-Style AI Brief
Click any node → Hook → Evidence → Connection → Next template. Shows WHY this matters, not just WHAT was found.
5
2-Level Drill-Down
Level 1: Pattern focus (which nodes match). Level 2: Click node in graph → full intelligence brief in sidebar with flash animation.
KEY DESIGN DECISIONS

Generic indicator filtering: "5+ sites within 300km" is the pattern DEFINITION, not a meaningful connection. We filter these out — only SPECIFIC traits create edges.

Honest "no edges" state: When no specific connections exist, the graph says so explicitly and tells the researcher what scan to run next.

Cross-pattern signatures: New signature IDs (am-gge-xpat-001, -002) represent connections BETWEEN sites, not attributes OF a single site.

Counter-arguments preserved: Every finding includes the strongest skeptical argument. This builds credibility — not advocacy.

Confidence taxonomy: STRONG = peer-reviewed/measurable. MODERATE = cited but not independently replicated. WEAK = anecdotal or single-source.
